```bash
papermind/.venv_new/bin/python scripts/test_backend_isolated.py
(cd web && npm test && npm run build && npm run lint)
(cd web && npm audit --omit=dev --audit-level=high)
# 首次需安装 Playwright Chromium；Linux CI 使用 --with-deps
(cd web && npx playwright install chromium && npm run test:pdf-reader)

python3 scripts/check_public_release.py
```

最后一项现在包含已选主许可证的存在性检查；删除 LICENSE 后仍应返回非零。脚本只检查文件是否存在且非空；前端护栏另核对官方全文与许可标识一致性。两者都不验证权属、历史凭据撤销或公开发布授权。

### 2026-09-21 第二批本地验收记录（PDF 升级后，历史结果）

本批 `fixed` 限于已确认的受影响依赖版本和升级过程复现的 API 兼容错误；不是已复现并封堵整站漏洞的结论。

- 安全边界：外部/上传 PDF 经 `getDocument` 到 canvas 和 TextLayer，当前源码未接入 PDFScriptingManager 或 sandbox。原包版本落入 [Mozilla 公告 GHSA-hq66-cqwq-w95j](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j) 的范围，但应用是否满足脚本执行前提未被证明。采用公告修复版 6.2.108，不增加脚本处理，不把无效的 `getDocument` 选项当成保护。

- 聚焦复现：直接升级后，实际浏览器在保存高亮时报 `convertToViewportRectangle` 不存在，在卸载时报 proxy `destroy` 不存在。改为点坐标转换和 loading task 销毁后，原高亮/卸载动作通过；零页处理中的同类调用同步替换。旋转坐标有 0/90/180/270 度单测。
- 安全替代检查：合成 PDF 同时含文档 OpenAction 和页面动作；先验证动作真实存在，再验证渲染时未设置动作标记、没有加载 scripting sandbox。同源请求仍有设备身份，跨源 PDF 无设备 ID / cookie。该测试是脚本与凭据边界回归，不是完整 CVE 利用复现。

## 公网试用是另一组条件

本轮代码已提供准入、预算、代理和配额。科研群试用前仍需实际启用并验收：

1. 在服务器逐个授权已有 UUID，再启用邀请模式；新用户私下领链接。关闭邀请模式不会提供撤销保护。
2. 设置供应商账户的实际金额上限；请求数预算不能精确限定 token 费用。
3. 部署本批代码，验收代理拒绝、试用邀请、PDF 阅读、上传与退出流程；服务器网络层的出站策略仍需按云环境配置。
4. 建立受控异地副本并检查备份定时器。现有本机恢复演练不代替服务器恢复验证。
5. 试用告知、第三方模型/诊断数据流、退出与删除方式。用于文章的问卷另行确认研究目的、同意与院内伦理流程；产品日志、个人印象和真实问卷不能混算。

本轮不改现有 UUID、不部署、不推送、不改仓库可见性；真实数据库只用于备份/恢复校验，未改写；未读取问卷，软著冻结材料未修改。作者已说明有人试用并回答问卷，但本轮没有拿到问卷内容，不能用日志或本地反馈表替代它，也不据人数判断能否投稿。

## 维护者发布顺序

主许可证与新私有仓库方案已确认。仅向新的 `papermind-source` 推送审查过的纯源码；原开发仓库与用户数据保持不动，不复制或重写旧历史。旧 OpenRouter 凭据的撤销、旧仓库可见性单独处理，不把更换服务商记为已撤销。

发布获准后，用 `prepare_source_release.py` 生成当前纯源码快照并复核清单，运行测试；不要压缩整个桌面项目目录。确定发布版本和对应源码地址，并在修改版在线服务中提供显著、可免费取得的源码入口。分清源码包与安装包的依赖许可。软著冻结版本、论文展示版本与拟发布版本各自标明，不自动覆盖旧材料。

已有线上服务若继续使用诊断上报，更新前应在服务器 `web/.env.local` 配置自己的 DSN 并重新构建；不要把 DSN 当作模型密钥，也不要重新硬编码作者项目。未配置会停止前端诊断上报，但不会移除页面错误恢复出口。此调整尚未部署。
