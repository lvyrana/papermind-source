# 研雀 · LitFinch 小范围试用指南

更新：2026-10-09。用途为产品可用性走查；研究问卷、量表和论文统计沿用各自方案。本指南不替换已有问卷，也不把操作记录直接计为研究结果。

当前 `0.7.0` 为本地候选，真实登录、原生安装和发布尚待验收。以下新版说明先供维护者准备，完成 [真实登录验收](zotero-login.md#真实验收记录待登记后执行) 后再随指定安装包发送；本轮没有招募或发放软件。

## 一、先确认收到的是哪一版

| 场景 | 入口与名称 | 适用说明 |
|---|---|---|
| 已有网页试用或旧 Connector 0.3.0 | 网页可能仍显示 PaperMind；旧插件右键为「用 PaperMind 精读」 | 使用主持人私下给出的已有访问方式，不会出现新版原生阅读台 |
| 历史本机安装 0.6.1 | Zotero 内阅读台，旧显示名 PaperMind | 旧安装记录，不能据此认为其他设备已验收 |
| 新版 Connector 0.7.0 候选 | 顶部「研雀」、阅读台与 Zotero 身份登录 | 使用明确标注版本的候选包；不能把 GitHub 旧公开包当作新版 |

网站与插件共享身份，不代表本地卡片自动同步到网页。试用期间固定使用一个入口完成一轮，记录使用的是网页还是 Zotero 阅读台。

## 二、给试用者：十分钟操作卡

准备一篇有权使用、带正常文字层的论文 PDF，固定用这一篇完成下列操作。不要使用患者资料、未公开敏感研究数据或院内受限文件。十分钟是安排建议，不是限时测验；卡住时记录停在哪一步即可。

### 新版 Zotero 阅读台

1. **打开论文**：在 Zotero 打开 PDF，点顶部「研雀」。核对阅读台题名与当前 PDF 一致。需要 AI 时按主持人给出的连接方式登录；提示“登录尚未启用”则先反馈，不自行申请 API Key。
2. **找阅读入口**：点「阅读路线」，再点「读摘要」。看完后，用一句话说出这篇论文研究什么；条目无摘要时改用「读当前页」，并记下这次替代。
3. **核对一段原文**：划选一个需要理解的句子，点「精读这段」。比较回答与原文，检查研究对象、数字和结论限定词；出现原文页码入口时点回 PDF。按钮成功响应与解释准确分别记录。
4. **留下自己的理解**：把需要保留的内容「存为卡片」，补一句自己的判断。再点卡片的原文页码，确认能回到对应位置。也可通过「写卡片」直接整理个人笔记。
5. **形成一个汇报条目**：从结果或卡片展开「送到汇报」，选一个合适板块；点底部「汇报板」查看。关掉阅读台后重开，确认刚才的卡片仍在。首次走查不必导出 Zotero 笔记，以免在真实文库留下不需要的测试内容。

翻译、自测和 Zotero 笔记导出可在这条主线完成后另试，不要求第一轮全部做完。

### 网页试用

使用电脑浏览器打开主持人提供的地址，从首页放入 PDF 或输入 PMID / DOI / 标题。进入阅读页后按同一主线操作：路线图或摘要带读 → 划词精读并核对原文 → 保存卡片 → 送到汇报板 → 重开论文查看记录。网页按钮名称与 Zotero 阅读台略有不同，反馈时标明入口。

未启用账号的旧服务使用匿名设备身份；启用账号的服务使用 Zotero 身份登录，并可能另需试用邀请。以该次服务实际提示为准，不能统一承诺“无需登录”。

## 三、安装、连接与换设备

新版发放前由维护者确认包名、版本和支持的 Zotero 版本。安装时先保存正在编辑的笔记，在 Zotero「工具 → 插件」中安装指定 `.xpi`；可将文件拖入插件窗口，或使用齿轮菜单的从文件安装入口。安装后核对版本，再打开一篇 PDF。[Zotero 官方安装说明](https://www.zotero.org/support/plugins)

服务已启用登录时，在阅读台点「登录」，到浏览器核对连接码，在 Zotero 官方页面确认身份，随后返回插件。已有 Zotero Desktop 同步登录不等于已经登录研雀。没有获得试用权限时，即使身份登录成功也可能暂不能使用 AI。

使用旧专属链接时，链接属于私有访问凭证，不转发到群聊或公开 Issue。已经关联到账号的旧空间须登录同一账号访问，单独复制旧链接不再够用。换设备前先确认记录位于网页服务器还是插件本机；插件卡片当前不会因登录同一账号自动迁移。

## 四、常见问题与数据说明

| 现象 | 先做什么 |
|---|---|
| 安装后没有「研雀」按钮 | 查看插件版本；0.3.0 只有旧网页入口。确认已经打开 PDF，而非只选中文献条目 |
| 显示登录尚未启用 | 把提示原文和版本发给主持人；不自行重建账号、不粘贴模型密钥 |
| 登录成功仍不能使用 AI | 查看邀请或用量提示；身份登录不自动授予邀请资格 |
| 当前页读不到文字 | 先试摘要或有可选文字的页面；扫描 PDF 的图片文字不属于当前原生阅读台的 OCR 能力 |
| 网页没有插件里的卡片 | 两处记录尚未自动同步；先回到原插件和原服务身份查找，不清空本地目录 |
| AI 回答与原文不符 | 记录错误类型和原文页码，例如数字不符、把相关写成因果、删掉“不确定”等限定词 |
| 超时、断网、次数已用完 | 保留未发送草稿，记录提示与时间；不要连续重试或反复切换账号 |

插件阅读台的卡片、草稿和汇报保存在本机；点击 AI 操作会向服务发送相关文字上下文。文献右键「用研雀精读」是另一条路径，会上传元数据和 PDF 到网页服务。网页产生的书架、笔记等保存在服务端。第三方模型提供商以实际部署配置为准，试用前由主持人说明。

退出登录、清理浏览器或卸载插件不会自动删除所有记录。需要删除时，优先从原身份的「设置 → 用户反馈」提出请求，不在正文或公开渠道粘贴专属链接、设备 ID、密码或密钥。插件本机记录、服务器记录、已导出的 Zotero 笔记与备份副本须分别处理。

用量以界面显示为准。当前源码默认推荐 5 批、对话类 60 次、翻译 120 次，自测另计；部署可覆盖这些值。个人额度与全服务预算分别计数，恢复时间以具体提示为准，不把服务器日界线当成每位试用者的本地零点。

## 六、给主持人：发放前与收尾

### 发放前

- [ ] 确认本轮入口、版本、指定安装包及已验收的系统范围；不把模拟浏览器通过记为原生 Zotero 通过。
- [ ] 完成 [登记与真实登录验收](zotero-login.md)；确认旧记录关联、退出、账号隔离和邀请规则。
- [ ] 准备一篇固定示例论文，记录来源、PDF 标识及可使用范围；不自动替试用者调用模型或写入文库。
- [ ] 说明实际服务运营者、模型服务、上传边界和删除联系渠道；研究性使用反馈另行取得相应同意。
- [ ] 核对个人额度和 `GLOBAL_DAILY_AI_REQUEST_LIMIT` 等全服务预算；owner 仍受全服务资源控制。
- [ ] 在 Python 3.12 隔离副本运行后端测试；网站测试与构建通过；不在维护者真实数据目录直接运行初始化型测试。
- [ ] 验证包含业务库、附件及已有账号库的备份，并在受控新目录恢复检查；参考 [部署与恢复](deployment-recovery.md)。不通过直接公网监听 HTTP 发放新版插件试用。

### 反馈台账

私有台账可记录：试用编号、邀请日期、入口和版本、是否实际打开、完成到哪一步、是否获得帮助、反馈原文、问题分类、复核结果。编号与联系人对应表分开保管，不把真实姓名或反馈写入 Git。

分别汇总已邀请、已使用、已反馈人数；未核实就留空。用户明确说出的评价属于真实反馈，服务日志属于使用痕迹，维护者判断属于个人印象。三类分栏，不能用匿名设备数量代替人数，也不能把自动测试结果填入试用表。

### 运行与收尾

每天检查备份执行结果及异地副本；当前脚本默认包含附件，不会自动按 30 天删除旧快照。达到容量上限时需核对并转移已验证快照。首页能打开只证明静态入口可用，还要检查 API、邀请、PDF 和登录链路。

收到删除请求后，先核对身份和删除范围。现有 `scripts/delete_user_data.py` 仅处理匿名 UUID 对应的业务数据与附件，不覆盖账号归属库、会话、插件本机记录及已导出的 Zotero 笔记；不得用它宣称“完整账号已删除”。本指南不自动执行删除。

收尾保存原始反馈和修复记录，完成私有备份，再决定下一轮邀请范围。真实反馈不随演示或源码包发出。
